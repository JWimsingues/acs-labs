= Exercise 5: Webhook notifier
:navtitle: Exercise 5: Webhook notifier

Estimated time: 15 minutes.

RHACS can push policy violation alerts to external systems using *notifiers*.
A *Generic Webhook* notifier sends a JSON payload via HTTP POST to any endpoint — making it compatible with monitoring systems like OpenITCockpit (Nagios-based), PagerDuty, ServiceNow, or any custom receiver.

In this exercise you will configure a webhook notifier, attach it to a policy, trigger a violation, and inspect the payload.

== Task 5.1: Create an external webhook receiver

You need a publicly reachable endpoint that accepts HTTP POST requests. https://webhook.site[webhook.site] provides a free, temporary endpoint for testing.

. Open https://webhook.site in a new browser tab.
. A unique URL is generated automatically (e.g. `https://webhook.site/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`).
. Copy this URL — you will use it in the next task.
+
Leave this tab open so you can see incoming requests in real time.

== Task 5.2: Create a Generic Webhook notifier in ACS

. In the RHACS Console, navigate to *Platform Configuration* > *Integrations*.
. Scroll down to the *Notifier Integrations* section.
. Click *Generic Webhook*.
. Click *Create integration*.
. Fill in the fields:
+
[cols="1,2",options="header"]
|===
|Field |Value

|Integration name
|`Lab - Webhook (OpenITCockpit)`

|Endpoint
|_(paste your webhook.site URL)_

|Skip TLS verify
|*Enabled* (webhook.site uses a public CA, but this simplifies testing)

|Audit logging
|*Disabled*
|===
+
. Leave *Headers* and *Extra fields* empty for now.
. Click *Test* to verify connectivity — you should see a test payload arrive at webhook.site.
. Click *Save*.

== Task 5.3: Attach the webhook to a policy

. Navigate to *Platform Configuration* > *Policy Management*.
. Search for the policy: *Latest tag*.
. Click the policy name to open its details.
. Click *Actions* > *Edit policy*.
. Navigate to the *Policy behavior* section (step 4 in the wizard).
. Under *Notification*, select *Lab - Webhook (OpenITCockpit)* from the notifier dropdown.
. Click *Save*.

TIP: You can attach multiple notifiers to a single policy — for example, both a webhook and Splunk.

== Task 5.4: Trigger a violation and inspect the payload

. On the bastion, create a deployment that uses the `latest` tag:
+
[source,bash]
----
oc create namespace webhook-test
oc run webhook-trigger --image=docker.io/library/nginx:latest -n webhook-test
----
+
. Wait a few seconds for ACS to detect the violation.
. Switch to the webhook.site browser tab.
. You should see a new POST request with a JSON payload.
. Click the request and review the payload structure:
+
[source,json]
----
{
  "alert": {
    "id": "...",
    "policy": {
      "name": "Latest tag",
      "severity": "LOW_SEVERITY",
      ...
    },
    "deployment": {
      "name": "webhook-trigger",
      "namespace": "webhook-test",
      ...
    },
    ...
  }
}
----

The payload includes the full policy details, deployment metadata, and violation context.

== Task 5.5: Discussion — mapping to OpenITCockpit

CTIE uses OpenITCockpit (Nagios-based) as the central monitoring system. To route ACS alerts there, you would:

. Deploy a small middleware service (or serverless function) that accepts the ACS webhook payload.
. Transform the JSON into a Nagios passive check result:
** *Host:* deployment namespace (e.g. `webhook-test`)
** *Service:* policy name (e.g. `Latest tag`)
** *State:* mapped from ACS severity (`CRITICAL_SEVERITY` → 2, `HIGH_SEVERITY` → 1, `LOW_SEVERITY` → 0)
** *Output:* violation summary text
. Forward the passive check to OpenITCockpit via its API or NSCA.

This mapping is not implemented in this lab, but the webhook payload contains all the fields needed for this integration.

== Cleanup

. Remove the test namespace:
+
[source,bash]
----
oc delete namespace webhook-test
----
. Detach the webhook from the policy:
** Navigate to *Platform Configuration* > *Policy Management*.
** Search for *Latest tag*, click the policy name.
** Click *Actions* > *Edit policy*.
** Navigate to *Policy behavior* (step 4).
** Remove *Lab - Webhook (OpenITCockpit)* from the notifier dropdown.
** Click *Save*.

== Key takeaways

* Generic Webhooks are the most flexible notifier type — any HTTP endpoint can receive ACS alerts.
* The JSON payload contains full policy, deployment, and violation context.
* Webhook.site is useful for prototyping; production systems use middleware to transform and route the payload.
* One policy can send alerts to multiple notifiers simultaneously.
