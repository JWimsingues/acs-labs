= Exercise 6: Splunk integration
:navtitle: Exercise 6: Splunk integration

Estimated time: 15 minutes.

RHACS integrates with Splunk in two ways:

* **RHACS Technology Add-on (TA-stackrox)**: a Splunk app that _pulls_ violations, vulnerability management data, and compliance results from the RHACS API on a schedule. This is already pre-installed in your environment.
* **Native Splunk notifier**: a _push-based_ integration where RHACS sends alerts to Splunk via the HTTP Event Collector (HEC) whenever a policy is violated. You will configure this in this exercise.

== Task 6.1: Explore the Splunk console

. On the bastion, get the Splunk web console URL:
+
[source,bash]
----
oc get route splunk-web -n splunk -o jsonpath='https://{.spec.host}'
----
+
. Open the URL in a browser and log in:
** *Username:* `admin`
** *Password:* `RhacsSplunkDemo123!`
. Navigate to *Settings* > *Apps* > *Manage Apps*.
. Confirm that *Red Hat Advanced Cluster Security* (package `TA-stackrox`) is installed and enabled.

The add-on is configured to pull violation and vulnerability data from the RHACS API automatically.

== Task 6.2: Check for add-on data

. Click *Search & Reporting* in the left sidebar.
. Run the following search to see violations pulled by the add-on:
+
[source,text]
----
index=* sourcetype="stackrox-violations"
----
+
. If data is present, review the fields: `alert_id`, `policy`, `deployment`, `namespace`, `severity`.

NOTE: The add-on's modular inputs poll on a schedule (violations every 5 minutes, vulnerability management every 4 hours). If no data appears, the add-on may not have completed its first pull yet. Continue with the next task. The push-based HEC integration you configure below works independently.

== Task 6.3: Configure the RHACS native Splunk notifier

The native notifier _pushes_ alerts in real time via HEC. Your environment has a pre-configured HEC token.

. On the bastion, retrieve the HEC token:
+
[source,bash]
----
oc exec deploy/splunk -n splunk -c splunk -- \
  curl -sk -u admin:RhacsSplunkDemo123! \
  "https://localhost:8089/services/data/inputs/http?output_mode=json" 2>/dev/null \
  | python3 -c "import sys,json;[print(e['content']['token']) for e in json.load(sys.stdin)['entry'] if e['name']!='http']"
----
+
Copy the token value printed to the terminal.
+
. In the RHACS Console, navigate to *Platform Configuration* > *Integrations*.
. Scroll to *Notifier Integrations* and click *Splunk*.
. Click *Create integration*.
. Fill in the fields:
+
[cols="1,2",options="header"]
|===
|Field |Value

|Integration name
|`Lab - Splunk HEC`

|HTTP Event Collector URL
|`http://splunk.splunk.svc.cluster.local:8088`

|HTTP Event Collector token
|_(paste the HEC token from the command above)_

|Source type
|`stackrox-alert`

|Skip TLS verify
|*Enabled*
|===
+
. Click *Test* to verify connectivity.
. Click *Save*.

TIP: The HEC URL uses the internal cluster service (`splunk.splunk.svc.cluster.local:8088`) because ACS Central and Splunk are on the same cluster. In production you would use the external HEC endpoint or a load-balanced URL.

== Task 6.4: Attach the notifier and trigger a violation

. Navigate to *Platform Configuration* > *Policy Management*.
. Search for the policy: *Curl in Image*.
. Click the policy name to open its details.
. Click *Actions* > *Edit policy*.
. Navigate to the *Policy behavior* section (step 4).
. Under *Notification*, select *Lab - Splunk HEC* from the notifier dropdown.
. Click *Save*.
. On the bastion, deploy a pod that contains `curl` into the pre-existing `frontend` namespace:
+
[source,bash]
----
oc run splunk-trigger --image=registry.access.redhat.com/ubi9/ubi:9.4 --command -- sleep 3600 -n frontend
----
+
. Wait approximately 30 seconds for ACS to scan the image and evaluate the policy.

== Task 6.5: Verify the alert in Splunk

. Return to the Splunk console.
. Run the following search:
+
[source,text]
----
index=* sourcetype="stackrox-alert"
----
+
. You should see events pushed by the RHACS native notifier.
. Click an event and review the JSON payload. It contains the full policy details, deployment metadata, and violation context.
. If the add-on also has data, compare the two sourcetypes:
+
[cols="1,1,1",options="header"]
|===
|Source |Sourcetype |Mechanism

|TA-stackrox add-on
|`stackrox-violations`
|Pull (scheduled)

|Native Splunk notifier
|`stackrox-alert`
|Push (real-time via HEC)
|===

== Cleanup

. Remove the test pod:
+
[source,bash]
----
oc delete pod splunk-trigger -n frontend
----

== Key takeaways

* RHACS offers two Splunk integration paths: a pull-based add-on (TA-stackrox) and a push-based native notifier (HEC).
* The add-on pulls violations, vulnerability management data, and compliance results on a schedule.
* The native notifier pushes alerts in real time, making it useful for SOC workflows that need immediate notification.
* Both can run simultaneously and produce different sourcetypes for distinct Splunk dashboards.
* The HEC URL can be an internal cluster service when ACS and Splunk share a cluster, or an external endpoint in production.
