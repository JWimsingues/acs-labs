= Exercise 4: OIDC group mapping & Console Plugin
:navtitle: Exercise 4: OIDC group mapping & Console Plugin

Estimated time: 15 minutes.

In the previous exercise you created a custom Role with a Permission Set and Access Scope.
Now you will connect an external identity provider (Keycloak) so that users authenticating via OIDC are automatically mapped to ACS roles based on their group membership.
You will also explore the *OpenShift Console Plugin*, which lets developers view RHACS vulnerability data directly inside the OpenShift Console without logging into ACS Central separately.

== Task 4.1: Review auth providers

. In the RHACS Console, navigate to *Platform Configuration* > *Access Control*.
. Select the *Auth providers* tab.
. Note the existing provider: *Login with username/password* (basic auth).
+
This is the default provider. You will now add an OIDC provider alongside it.

== Task 4.5: Explore the OpenShift Console Plugin

The RHACS Console Plugin is already enabled on this cluster. It adds vulnerability data directly into the OpenShift Console.

. Open the *OpenShift Console*: https://console-openshift-console.apps.cluster-sz6zn.dyn.redhatworkshops.io
. Log in as `admin` / `CyIDoW06RdLv`.
. Navigate to *Home* > *Overview*.
. Notice the *ACS* section in the status card — it shows a cluster-wide vulnerability summary.
. Navigate to *Workloads* > *Deployments*.
. Select any deployment and scroll down.
. Look for the *Vulnerabilities* tab — this shows CVE data from RHACS for that specific workload, without leaving the OpenShift Console.

TIP: The Console Plugin is especially useful for developers who operate in the OpenShift Console daily. They can check their workload's vulnerability posture without needing a separate ACS login or different RBAC configuration.

== Key takeaways

* OIDC auth providers let you map external identity groups (Keycloak, Azure AD, Okta) directly to ACS roles.
* Combined with SAC (Exercise 3), OIDC group mapping automates tenant isolation — no manual role assignment per user.
* The OpenShift Console Plugin embeds vulnerability data into the developer's native workflow.
* Both mechanisms reduce the friction for development teams to engage with security data.
